# 高中数学 AI 备课工作台：开发边界与后续路线图 v2

日期：2026-08-13  
适用阶段：单人教师内部 Alpha → 封闭试用 MVP → 商业 V1

## 1. 当前产品定位

当前产品是一套面向项目所有者本人使用的“教师优先、题库质量门禁优先”的高中数学备课工作台。

当前版本已经跑通：

`资料登记 → PDF 分析 → 拆题校对 → 公式/图片处理 → 私人题库 → 人教 A 版教材映射 → 数学核验 → 教师审核 → 搜题/解题/教案/组卷/导出`。

当前版本不是可以直接开放注册和收费运营的商业 SaaS。现阶段的核心目标不是继续增加零散页面，而是把题库生产、质量控制和教师审核做深，使可发布题库从几十道稳定扩展到至少 2,000 道。

## 2. 下一阶段开发边界

### 2.1 本阶段必须完成

本阶段只建设以下能力：

1. 题目去重与变式识别：区分完全重复、去除年份地区后的同题、同题异解、真正变式和无关题。
2. 教师去重审核工作台：所有合并、保留或标记变式决策由教师确认。
   - 教师确认后可以勾选关系组内任意一道或多道题软移出正常题库；不永久删除正文、解析、图片、来源或审核记录。
   - 软移出题默认不参与搜题、组卷、教案与推荐，但保留直接审计访问和恢复入口。
3. 题库覆盖率与缺题分析：按人教 A 版知识点、题型、难度和新高考Ⅰ卷优先级显示缺口。
4. PDF 加工质量仪表：拆题准确率、公式修正率、人工处理时间、映射置信度和失败原因。
5. 混合搜索与 RAG 基础：在结构化题库稳定后，实现关键词、公式和语义三路召回，并展示可追溯来源。
6. 教材目录发布版本：审核完成后形成可回滚的人教 A 版目录版本。

### 2.2 本阶段明确不做

在题库生产与质量指标稳定前，不进入以下范围：

- 学生端、家长端、作业发布、在线答题和自动批改；
- 学校采购后台、教研组多人审批和复杂组织结构；
- 原生 iOS/Android App；
- 公网开放注册、正式收费和大规模营销；
- 模型微调、从零训练数学模型或未经评测的自动发布；
- 无教师确认的批量合并、批量发布和 AI 数学结论；
- 为单一页面复制检索、映射、去重或验证规则。

### 2.3 技术边界

- 继续采用 Next.js + FastAPI 的模块化单体，不提前拆微服务。
- 单人本地阶段继续使用 SQLite 和本地文件系统，但模块接口不得依赖 SQLite 细节。
- 云端阶段再迁移 PostgreSQL、pgvector、Redis 与对象存储。
- 教师/管理员切换在当前阶段只是工作模式，不是安全认证。
- 所有 AI 输出必须保留来源、模型运行记录、提示版本和教师审核状态。
- 所有题目合并或状态变更必须保留可审计记录，不直接覆盖来源证据。

### 2.4 数据与内容边界

- 只把来源声明明确、可进入私人加工区的资料纳入处理。
- 不复制原 PDF 的封面、水印、版式和大段原创讲义表述。
- 题目事实、重新组织的题干和教师自有解析与原文件分开存储。
- 自动识别结果只是候选；低置信度公式、图片归属、教材映射、重复关系和数学结论必须人工复核。
- 商业发布前仍需逐批核对来源声明、授权范围和下架能力。

## 3. 后续完整开发计划

### 阶段 A：题库去重与变式识别（当前立即执行）

交付内容：

- 统一文本、公式、选项和答案的规范化指纹；
- 候选对生成，避免全量两两比较；
- 五类关系：完全重复、同题不同来源、同题异解、真正变式、非重复；
- 置信度、命中证据、来源对照和教师审核记录；
- 管理员工作台支持确认、排除和保留为变式；
- 检测结果不能自动删除题目；第一版也不做破坏性合并。

完成标准：

- 对现有题库和后续 PDF 导入题可重复扫描；
- 同一候选对不会重复创建；
- 教师决策可追溯；
- 题干修改后旧检测结果标记为过期；
- 自动测试覆盖规范化、候选生成、分类、幂等和审核门禁。

### 阶段 B：覆盖率与题库缺口分析

交付内容：

- 人教 A 版五册知识点覆盖率；
- 题型、难度、验证状态、教师审核状态分布；
- 新高考Ⅰ卷结构需求与当前可用题量差距；
- “下一个最值得加工的 PDF/专题”建议；
- 可发布题、待核验题和来源冲突题分层统计。

完成标准：指标均能回溯到题目集合，不显示无法解释的估算数字。

### 阶段 C：PDF 加工质量仪表

交付内容：

- 拆题确认率、公式自动修复率、图片裁剪率；
- 每题平均人工操作次数和处理时间；
- 教材映射高/低置信度分布；
- OCR、公式、图片、来源配对失败原因；
- 文件和批次级质量对比。

完成标准：能够据此决定 OCR 服务、模型和下一批资料，而非只展示进度。

### 阶段 D：混合检索与可追溯 RAG

交付内容：

- 关键词检索、数学公式特征检索、语义向量检索；
- 章节、题型、难度、验证、审核和来源过滤；
- 去重后的结果多样性控制；
- 回答引用具体题目、教材节点和来源页；
- 无可靠证据时明确拒绝给出确定结论。

完成标准：用固定评测集比较召回率、教师选择率、重复率和无证据回答率。

### 阶段 E：教材目录正式版本与回滚

交付内容：

- 教材目录审核完成度；
- 发布版本、变更记录和回滚；
- 题目映射受目录版本约束；
- 目录升级时提供影响分析。

完成标准：生产题库不直接依赖未审核的目录草稿。

### 阶段 F：账户、云端隔离和商业基础设施

启动前提：题库质量流程稳定，至少完成一次封闭教师试用。

交付内容：

- 登录、会话、密码或第三方身份；
- 服务端 RBAC；
- 用户、组织、套餐和管理员授权模型；
- PostgreSQL、对象存储、后台任务队列；
- 多租户数据隔离、备份、恢复和下架；
- 订阅、订单、支付、退款和额度。

完成标准：通过越权测试、恢复演练和支付沙箱闭环后，才允许开放收费。

### 阶段 G：模型评测、成本治理与可选微调

交付内容：

- 教案、变式、解题、OCR、教材映射的固定评测集；
- 数学正确率、教师接受率、编辑距离、延迟和成本；
- 多模型路由与降级；
- 教师修改数据治理；
- 只有在数据量和收益明确时才评估微调。

完成标准：模型更换或提示升级必须先通过离线评测和小流量教师验收。

### 阶段 H：商业 V1 上线准备

交付内容：

- 至少 2,000 道达到发布门禁的结构化题；
- 搜题、教案、解题、变式、组卷、导出端到端稳定；
- 监控、告警、备份、恢复、限流和内容下架；
- 用户协议、隐私政策、版权投诉流程、备案和支付主体；
- 封闭测试问题清零和上线检查表。

## 4. 开发优先级与停止条件

固定优先级：

1. 数学正确性与来源证据；
2. 教师审核效率；
3. 可恢复、可追溯的数据变更；
4. 题库覆盖率；
5. 搜索与生成体验；
6. 商业功能；
7. 非核心视觉装饰。

若出现以下任一情况，应停止扩大数据规模并先修复：

- 数学错误题被系统标记为可发布；
- 教师修改后旧验证或去重结论仍被当作有效；
- 来源页或权利声明丢失；
- 公式、图片或导出结果无法可靠复核；
- 同一操作重复执行造成重复数据；
- 角色模式被误当作真实安全认证。

### 4.1 需求澄清规则

- 遇到产品功能含义、教师工作流、业务规则、数据处置、发布门禁或范围取舍不明确时，必须立即向项目所有者提问，不得自行编造。
- 已被本文档、既有界面或用户明确确认的功能规则，可以继续执行，无需重复确认。
- 纯代码实现、明确缺陷修复、测试、重构、兼容性和性能问题由 Codex 自主处理，不因技术细节打断项目所有者。
- 若一个代码选择会实际改变用户功能或数据含义，则按功能问题处理，必须先询问。

## 5. 当前里程碑

当前里程碑：`M3 题库规模化生产与质量治理`。

本里程碑顺序：

1. 题目去重与变式识别；
2. 覆盖率与缺题分析；
3. PDF 加工质量仪表；
4. 混合搜索与 RAG；
5. 教材目录正式版本。

账户、支付和学生端不属于 M3。

## 6. 2026-08-13 治理修复落点

- 教材审核页与写入接口已经退役；教案和题目映射统一读取只读的人教 A 版基线，启动时校验目录文件 SHA-256，防止目录被无意改写。
- 批量导入题目可以凭草稿题号直接进入题库审核，不再出现导入成功但搜索结果为零。
- 私有字体映射损坏的 PDF 必须先经过本地数学 OCR 或人工转录；旧乱码文本不得导出。OCR 草稿仍须教师对照原页确认。
- 教案、试卷、资料、导入批次、批次内单份 PDF 与题目均采用可恢复的软移除；永久清除及级联范围在项目所有者确认前不开放。
- DeepSeek 已作为教案、题目变式与解题的可选文本模型接入；视觉 OCR 独立走本地数学 OCR 或经单次授权的视觉服务。
- 下一步继续执行 M3：先完善 PDF 加工质量仪表，再建设混合搜索与可追溯 RAG；不在本阶段扩展学生端、付费或多租户能力。

## 7. 2026-08-14 角色与模型调用边界

- 教师模式是“成型内容使用台”：保留备课、搜题、解题、教案和组卷；不展示资料 OCR、批量导入、题库审核队列、发布门禁、回收站和来源治理操作。
- 管理员模式是“内容治理台”：保留全部题库修订、验证、来源、去重、资料 OCR、批量加工和发布能力，同时也拥有教师的搜题与变式功能。
- 教师修改正式题目时不得覆盖母题，必须另存为可追溯的私人变式；私人变式可供创建者立即使用，进入公共正式题库前仍须管理员审核。
- DeepSeek 可以为教师当前编写的变式独立计算答案和解析草稿；计算结果只回填编辑器，教师可以继续修改，且不等同于数学验证通过。
- 模型生成、LaTeX 修复和 OCR 属于长任务，不通过有约 30 秒限制的网页开发代理；OCR 与整卷修复使用可查询状态的后台任务，避免前端超时后后台仍持续计费。
- DeepSeek 的 JSON 先做传输层容错，再由业务 Schema 严格验证；解题、变式、教案分别设置输出上限，避免失败重试造成异常 Token 消耗。
- 正式母题由管理员维护，管理员修订会同步影响教师看到的正式题；教师修订只能写入当前教师所有的私人派生题，不反向修改正式母题，也不向其他教师开放。
- 变式采用“教师先写、AI 后辅助”：教师先修改题干、条件、数值或选项，DeepSeek 只可润色教师原稿或计算答案，不提供一键替教师生成整道变式的界面。
- 解题助手同时保留标准解法与第二种解法，生成第二种解法后必须可以无额外模型调用地来回查看两份结果。
