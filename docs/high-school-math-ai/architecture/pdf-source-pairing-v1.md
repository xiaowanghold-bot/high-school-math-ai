# PDF 原题与解析来源配对 v1

## 目标

在拆题前识别“学生版/原卷版 + 解析版”关系，并区分题解同文件资料。配对只建立来源关系，不把原解析直接发布，也不绕过公式、数学验证和教师审核门禁。

## 模块接口

`PdfImportStudio` 在同一接口后隐藏角色识别、标题净化、题量一致性、置信度计算、候选持久化和教师审核：

- `source_pairing(file_id)`：返回单个文件的角色、覆盖状态和配对候选；
- `propose_source_pairs()`：扫描全部已登记文件，新增高置信度候选，但不覆盖既有审核决定；
- `review_source_pair(pair_id, command)`：确认或排除候选，并保留审核人、备注和时间。

HTTP 只负责输入与错误映射：

- `GET /api/v1/imports/files/{file_id}/source-pairing`
- `POST /api/v1/imports/source-pairs/propose`
- `PATCH /api/v1/imports/source-pairs/{pair_id}`

## 角色与状态

文件角色包括：仅题目、答案参考、题解同文件和待识别。覆盖状态包括：无需额外配对、已确认配对、发现候选和尚未配对。

解析版、教师版或老师版默认识别为题解同文件；原卷版和学生版默认识别为仅题目。标题没有明确标记时，再使用已分析页面中的题号和答案标记辅助判断。

## 匹配策略

候选置信度综合：

1. 去掉“原卷版、学生版、解析版、教师版”等角色词后的标题相似度；
2. 题量估计或题号数量的一致性；
3. 解析来源是否同时包含题目和解析。

当前阈值为 `0.72`，每份原题最多保留 3 个候选。禁止使用固定页码差。确认一个候选后，同一原题文件的其余未审核候选自动排除；再次扫描不会恢复已排除候选。

## 数据与安全门

`import_source_pairs` 保存两端文件、置信度、判断信号、策略版本和教师审核记录。确认配对后的使用规则仍是：

- 题干事实来自原题文件；
- 答案只作为独立数学验证的种子；
- 原解析文字不直接进入产品展示；
- 两份文件按一套唯一题集计数；
- 逐题关联、数学验证与教师审核仍需在后续阶段完成。
