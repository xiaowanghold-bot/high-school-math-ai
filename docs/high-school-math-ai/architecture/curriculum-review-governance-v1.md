# 教材目录审核治理 v1

## 目标

让教师能在不改写课程目录 CSV 的前提下，对人教 A 版五册目录逐项修订、保存草稿、批准或退回，并让最新有效内容即时用于目录搜索、题库课程映射和教案生成。

## 模块边界

`CurriculumGovernance` 对外只暴露三类业务操作：

- `workspace`：按册次、层级、状态和关键词取得审核队列及统计。
- `inspect`：同时返回原始节点、当前有效节点和完整审核历史。
- `submit`：追加草稿、批准或退回记录，可显式级联到下级节点。

路由和界面不直接操作 SQLite，也不自行合并课程字段。覆盖规则集中在 `ReviewedCurriculumCatalog` 中，避免教案、题库和搜索各自实现一套状态判断。

## 数据策略

- `data/curriculum/pep-a-curriculum.csv` 是不可变的基础目录。
- `data/runtime/curriculum-reviews.sqlite3` 保存追加式审核记录，不纳入 Git。
- 每次提交生成独立 `review_id` 和 UTC 时间；历史记录不覆盖、不删除。
- 每个节点以最后一条记录决定审核状态。
- `draft` 与 `approved` 的字段修订构成教师端有效目录；`changes_requested` 仅改变状态，不应用本次修改字段。

这种设计保留了原始教材映射、教师修订和最终批准之间的可追溯差异，后续可自然扩展为多人审核、版本发布和回滚。

## 级联规则

- 册、章、节可在教师明确勾选后级联处理全部后代节点。
- 知识点是末级节点，不允许级联。
- 级联时，编辑字段只应用于当前节点；后代节点只继承审核决定、意见、审核人和时间。
- “批准本册全部”需要浏览器二次确认，系统不会自动执行。

## 下游读取

`ReviewedCurriculumCatalog` 动态叠加最新审核记录，并保持原目录接口：`get_node`、`get_tree`、`search`、`path_for`。因此：

- 教材目录页展示有效名称和状态；
- 课程搜索可以检索教师修订后的题型、说明和名称；
- 题库质量工作流使用有效课程映射；
- 新生成的教案使用有效课程上下文。

已生成的历史教案不会被目录修订自动改写。

## 状态语义

| 审核状态 | 有效内容 | 含义 |
| --- | --- | --- |
| `pending` | 基础目录 | 尚未产生教师记录 |
| `draft` | 基础目录 + 草稿修订 | 教师私有流程可试用，尚未终审 |
| `approved` | 基础目录 + 批准修订 | 教师终审完成 |
| `changes_requested` | 基础目录 | 已标记需重新修订 |

## 当前限制与后续扩展

- v1 使用单一默认审核人 `owner_teacher`，尚未接入账户系统。
- v1 没有“发布批次”概念；商业上线前应在审核状态之上增加可回滚的目录版本。
- v1 的 397 个节点适合直接读取最新记录；数据扩大后可增加 latest-review 物化表或窗口查询。
