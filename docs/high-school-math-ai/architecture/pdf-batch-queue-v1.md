# PDF 批量加工队列 v1

## 目标

让 31 份、约 2209 页的 PDF 资料能够分批可靠加工，而不是依赖一次长时间请求。队列只负责页面分析和进度控制，不绕过题目边界、公式、图片、数学验证和教师审核门禁。

## Module 与 Interface

`PdfImportStudio` 继续作为 PDF 加工 Module。新增的队列 Interface 只有三个主要操作：

- `queue_batch(batch_id)`：把待分析、暂停、失败或异常中断的文件放回队列；已完成文件不会重复处理；
- `process_next(batch_id, page_budget)`：认领队首文件并处理一个有限页组；每页完成后立即持久化检查点；
- `pause_batch(batch_id)`：暂停尚未开始的页组，当前页组结束后可安全停止。

页面、命令行脚本和未来后台 worker 都跨同一个 Seam 调用这些操作。SQLite 是当前 Adapter；以后替换为 Redis 队列或云任务系统时，教师校对页面不需要理解调度细节。

## 检查点与恢复

每处理一页，系统立即写入：

- 页码、尺寸、提取文本和字符数；
- 题号标记、内嵌图片数和文字层状态；
- 文件级累计页数、文本页、扫描页、字符、题号和图片指标。

如果某页失败，文件进入 `failed`，此前页面保留。重试时从第一个未完成页继续。正常分段处理后文件回到 `queued`；全部页面完成后才进入 `ready_for_segmentation`。

## 状态

文件状态为：

- `registered`：已登记，尚未入队；
- `queued`：等待下一页组；
- `analyzing`：当前页组正在处理；
- `paused`：教师暂停，检查点已保存；
- `failed`：本轮失败，可重试；
- `ready_for_segmentation`：全部页面分析完成，可进入拆题。

## 题量估计

登记文件时按文件名匹配题量审计表。估计值只用于排期和覆盖率统计，不能代替最终边界候选数量。旧批次在启动时会补齐已有审计值。

## 首批真实资料验证

使用以下三份资料副本完成了临时压力验证：

- 《大题 函数与导数（解析版）》53 页；
- 《概率统计（精选30题）（解析版）》38 页；
- 《大题 立体几何（精选30题）（解析版）》39 页。

共 130 页，按每轮 25 页运行 7 个页组，最终 3 份全部完成、0 份失败；题量审计估计 100 题，页面文本提取检测到 108 个题号标记。两者只是不同口径，后续以教师确认的题目边界为准。
