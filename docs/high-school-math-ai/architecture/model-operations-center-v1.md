# 模型运行中心 v1

## 目标

模型运行中心把教案生成、教案局部改写、题目变式、解题助手和私人资料 OCR 的运行状态收敛到一个独立模块。管理员通过 `/admin/models` 查看实际能力路由和运行质量，不需要进入每个教师页面逐一排查。

## 模块边界

`ModelOperationsRegistry` 是统一的运行观测模块，向模型适配器暴露一个很小的 Interface：

- `track(...)`：开始一次运行并接收功能、适配器、模型、提示版本和执行者标识；
- `capture_response(...)`：从 Responses API 返回值提取 token 用量；
- 上下文结束时自动记录成功、失败和端到端耗时；
- `dashboard(...)`：输出只读的配置摘要、能力路由、汇总指标和最近记录。

外部模型仍由各业务模块的 Adapter 负责调用，业务模块不直接写 SQLite。没有外部模型时，本地教案模板和本地诊断规则也通过同一 Seam 记录运行，便于区分“系统无调用”和“系统使用了本地降级能力”。

## 保存内容

每次运行保存：

- 功能、适配器、模型和提示版本；
- 成功或失败、错误类别和脱敏后的短错误信息；
- 输入、缓存输入、输出和总 token；
- 耗时、可选的成本估算和执行者标识；
- 运行时间。

运行记录不保存题目正文、教案正文、提示词内容、模型完整输出、原文件或 API Key。错误信息会清除常见密钥格式并截断，避免管理页面成为教学资料或凭据泄露面。

## 成本策略

模型价格会变化，因此代码不硬编码供应商价目表。只有同时配置输入、缓存输入和输出三项“每百万 token 美元费率快照”时，系统才在运行发生时估算成本；否则页面只展示 token，并明确标记“尚未配置费率快照”。

## 当前限制

- 首版是单人项目的运营视图，管理员页面门禁仍是客户端工作模式，不等同于生产级服务端鉴权；
- 运行记录保存在本地 SQLite，尚未实现按组织隔离、保留周期和归档；
- 解题助手命中题库已验证答案时不发生模型调用，目前只在能力路由中显示，不计入模型运行次数；
- 成本为费率快照估算值，不作为账单依据。
