# 高中数学 AI 备课工作台：项目执行基线 v1

日期：2026-08-03

## 1. 已确认的协作模式

- 项目所有者、产品最终决策者、数学教师审核者：用户本人。
- 产品规划、信息架构、UI 设计、技术架构、编码、测试、文档和技术运维方案：Codex 协助完成。
- 不假设存在外部设计师、工程团队、测试团队或额外学科审核人员。
- 涉及公司主体、域名、云账号、支付签约、备案和需要本人实名完成的事项，由用户执行；Codex 提供材料、清单和操作指导。
- 教学内容的最终发布门禁由用户以教师身份确认，AI 预检不能替代教师签字。

## 2. 对原规划的调整

### 保留

- 教师端 Web/PWA。
- 人教 A 版优先、新高考全国 I 卷优先。
- 搜题、教案、题目生成、解题、组卷和导出六条核心工作流。
- 大模型接口、RAG、数学验证器和教师确认。
- PostgreSQL、pgvector、Redis 和对象存储。

### 简化

- 首版采用单仓库、模块化单体和单生产环境，不拆微服务。
- 首版只实现普通教师和管理员两种身份；两者可由同一账号切换。
- 审核流简化为 `AI预检 → 教师确认 → 发布/退回`。
- 不在首版建设教研组多人审批、复杂组织结构、学校采购后台和原生 App。
- 自动化测试优先覆盖高风险深模块和核心用户流程，不追求低价值代码覆盖率。

## 3. 单人项目的完成顺序

1. 先固定数据结构和模块接口。
2. 先做审核后台，再扩大题库。
3. 先做搜题和题目详情，再做教案生成。
4. 先实现可编辑教案，再增加复杂模板。
5. 先完成单项选择题验证，再逐类扩展数学验证器。
6. 先支持标准 DOCX/PDF，再支持学校自定义模板。
7. 先封闭自用，再邀请其他教师测试，最后开放收费。

## 4. 用户与 Codex 的验收协议

每个功能经历以下状态：

- `specified`：需求、范围和验收标准明确。
- `implemented`：代码完成并通过自动测试。
- `technical_verified`：核心流程、错误处理和数据迁移通过。
- `teacher_reviewed`：用户以教师身份完成可用性与数学内容审核。
- `accepted`：可以进入下一阶段或发布。

用户反馈以具体页面、操作步骤、期望结果和实际问题为准。Codex 负责定位、修改、测试并更新相关文档。

## 5. 商业 V1 的完成定义

同时满足以下条件才视为商业 V1 完工：

- 人教 A 版必修第一册知识点树完整可用。
- 至少 2,000 道达到发布门禁的结构化题目。
- 搜题、教案、解题、题目生成、组卷、导出可以端到端完成。
- 客观题验证、来源追踪、AI 标识和私人资料隔离生效。
- 教师账户、套餐额度、订单和支付闭环可用。
- 核心流程通过自动测试和用户教师验收。
- 生产环境具备日志、监控、备份、恢复和内容下架能力。
- 上线所需协议、备案和合规事项完成或经专业意见确认不适用。
